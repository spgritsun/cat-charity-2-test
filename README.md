# QRKot — благотворительный фонд поддержки котиков

Приложение для Благотворительного фонда поддержки котиков. Фонд собирает
пожертвования на целевые проекты: закупку корма, обустройство кошачьей
колонии, медицинское обслуживание, регистрацию кошек как имущества.

## Как это работает

В фонде есть **целевые проекты** и **пожертвования**. Каждому проекту задаётся
требуемая сумма, каждое пожертвование приходит с суммой от жертвователя.
Средства распределяются автоматически, без ручного вмешательства:

- при создании нового проекта в него сразу переводятся все свободные
  (ещё не распределённые) деньги из ранее полученных пожертвований;
- при получении нового пожертвования деньги сразу распределяются
  по открытым проектам — от самых старых к новым.

Как только проект набирает требуемую сумму, он закрывается: у него
проставляются признак `fully_invested` и дата закрытия `close_date`.
Так же закрывается и пожертвование, все деньги которого разошлись по проектам.
Распределение и создание объекта выполняются одной транзакцией, поэтому
ситуация «проект создан, а деньги не распределились» невозможна.

Каждое пожертвование привязано к пользователю, который его сделал:
в модели `Donation` за это отвечает внешний ключ `user_id`.

## Пользователи и права доступа

Регистрация и аутентификация построены на библиотеке **FastAPI Users**.
Идентификатор пользователя — целое число, токен передаётся в заголовке
`Authorization: Bearer <token>`, формат токена — JWT.

| Роль                          | Что может                                                                 |
|-------------------------------|---------------------------------------------------------------------------|
| **Анонимный пользователь**    | Смотреть список всех проектов, зарегистрироваться                          |
| **Зарегистрированный**        | То же самое, плюс делать пожертвования и смотреть список **своих**         |
| **Суперпользователь**         | То же самое, плюс управлять проектами и видеть **все** пожертвования       |

В списке своих пожертвований обычному пользователю возвращаются только четыре
поля: `id`, `comment`, `full_amount`, `create_date`. Информация о том,
распределено пожертвование по проектам или нет, доступна только
суперпользователю.

Запрещено всем, независимо от уровня доступа:

- удалять пользователей (эндпоинт отключён);
- редактировать и удалять пожертвования;
- редактировать и удалять закрытые проекты;
- удалять проекты, в которые уже поступили средства;
- менять даты создания и закрытия проектов.

## Возможности API

**Проекты и пожертвования**

| Метод  | Эндпоинт                        | Доступ         | Что делает                          |
|--------|---------------------------------|----------------|-------------------------------------|
| GET    | `/charity_project/`             | все            | Список всех целевых проектов        |
| POST   | `/charity_project/`             | суперюзер      | Создать проект                      |
| PATCH  | `/charity_project/{project_id}` | суперюзер      | Отредактировать проект              |
| DELETE | `/charity_project/{project_id}` | суперюзер      | Удалить проект                      |
| POST   | `/donation/`                    | авторизованный | Сделать пожертвование               |
| GET    | `/donation/my`                  | авторизованный | Список своих пожертвований          |
| GET    | `/donation/`                    | суперюзер      | Список всех пожертвований           |

**Регистрация и аутентификация**

| Метод  | Эндпоинт            | Доступ         | Что делает                          |
|--------|---------------------|----------------|-------------------------------------|
| POST   | `/auth/register`    | все            | Зарегистрировать пользователя       |
| POST   | `/auth/jwt/login`   | все            | Получить токен                      |
| POST   | `/auth/jwt/logout`  | авторизованный | Выйти                               |
| GET    | `/users/me`         | авторизованный | Данные текущего пользователя        |
| PATCH  | `/users/me`         | авторизованный | Изменить свои данные                |
| GET    | `/users/{id}`       | суперюзер      | Данные пользователя по id           |
| PATCH  | `/users/{id}`       | суперюзер      | Изменить данные пользователя        |

Эндпоинт `DELETE /users/{id}` намеренно отключён: пользователей в этом
приложении не удаляют. Вместо удаления учётную запись можно деактивировать,
сняв флаг `is_active` через `PATCH /users/{id}`.

Ограничения при работе с проектами:

- название проекта уникально, длина от 5 до 100 символов;
- описание — не короче 10 символов;
- требуемая сумма — целое число больше нуля;
- закрытый проект редактировать нельзя;
- нельзя установить требуемую сумму меньше уже внесённой в проект;
- нельзя удалить проект, в который уже поступили средства.

Пожертвования не редактируются и не удаляются — по смыслу это уже
совершённое действие.

## Технологии

- Python 3.10+
- FastAPI
- FastAPI Users (аутентификация, JWT + Bearer)
- SQLAlchemy 2.0 (асинхронный движок)
- Alembic
- Pydantic 2
- SQLite + aiosqlite
- pytest

## Установка и запуск

Клонировать репозиторий и перейти в его директорию:

```bash
git clone https://github.com/spgritsun/cat-charity-2.git
cd cat-charity-2
```

Создать и активировать виртуальное окружение:

```bash
python -m venv venv
source venv/bin/activate      # Linux / macOS
venv\Scripts\activate         # Windows
```

Установить зависимости:

```bash
pip install -r requirements.txt
```

Создать файл `.env` на основе примера и подставить свои значения:

```bash
cp .env.example .env          # Linux / macOS
copy .env.example .env        # Windows
```

Переменные окружения:

| Переменная                  | Обязательна | Назначение                                            |
|-----------------------------|-------------|-------------------------------------------------------|
| `APP_TITLE`                 | нет         | Название приложения в документации                    |
| `DESCRIPTION`               | нет         | Описание приложения в документации                    |
| `DATABASE_URL`              | нет         | Строка подключения к базе данных                      |
| `SECRET`                    | да          | Ключ для подписи JWT-токенов                          |
| `JWT_LIFETIME_SECONDS`      | нет         | Время жизни JWT-токена в секундах (по умолчанию 3600) |
| `FIRST_SUPERUSER_EMAIL`     | нет         | Email первого суперпользователя                       |
| `FIRST_SUPERUSER_PASSWORD`  | нет         | Пароль первого суперпользователя                      |

Если заданы обе переменные `FIRST_SUPERUSER_*`, суперпользователь создаётся
автоматически при старте приложения. Если хотя бы одна не задана — не
создаётся, и приложение запускается как обычно.

Применить миграции:

```bash
alembic upgrade head
```

Запустить приложение:

```bash
uvicorn app.main:app --reload
```

Приложение будет доступно по адресу http://127.0.0.1:8000.

## Документация

После запуска доступна интерактивная документация:

- Swagger UI — http://127.0.0.1:8000/docs
- ReDoc — http://127.0.0.1:8000/redoc

Чтобы отправлять запросы из Swagger UI от имени пользователя, нажмите
кнопку **Authorize** и введите email и пароль — токен подставится в запросы
автоматически.

## Тесты

```bash
pytest
```

Кроме автотестов, в каталоге `postman_collection/` лежит готовая
Postman-коллекция `QRKot_2.postman_collection.json` — набор запросов для
проверки API целиком, включая регистрацию, права доступа и распределение
средств. Запускать её нужно на пустой базе:

```bash
alembic upgrade head
python setup_for_postman.py   # создаст суперюзера root@admin.ru / root
uvicorn app.main:app --reload
```

Подробный порядок запуска описан в `postman_collection/README.md`.

## Структура проекта

```
app/
├── api/
│   ├── endpoints/    # обработчики запросов к проектам, пожертвованиям и пользователям
│   ├── constants.py  # тексты сообщений об ошибках
│   ├── deps.py       # зависимости FastAPI (сессия БД)
│   ├── responses.py  # описания ответов с ошибками для Swagger
│   ├── routers.py    # сборка роутеров и теги документации
│   └── validators.py # проверки бизнес-правил
├── core/
│   ├── config.py     # настройки приложения из переменных окружения
│   ├── db.py         # подключение к базе и общий базовый класс моделей
│   ├── init_db.py    # создание пользователей и первого суперпользователя
│   └── user.py       # настройка FastAPI Users: JWT, Bearer, UserManager
├── crud/             # операции с объектами в базе данных
├── models/           # ORM-модели CharityProject, Donation и User
├── schemas/          # схемы Pydantic для запросов и ответов
├── services/         # логика распределения средств между проектами
└── main.py           # точка входа

alembic/              # миграции базы данных
postman_collection/   # коллекция запросов для проверки API
tests/                # тесты
```
